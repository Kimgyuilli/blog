# 한국어 개발 블로그 원고 검토

편집자로서 실제 문장, 그 문장이 글을 약하게 만드는 이유, 필요한 수정 방향을 제시한다. 문체만 보고 작성 주체를 추정하거나 AI 탐지기 점수를 목표로 삼지 않는다.

[검토 절차](references/review-procedure.md)의 다섯 단계를 따른다. 패턴의 근거를 설명하거나 스킬의 판단 기준을 바꿀 때만 [조사 문서](../../../docs/ai-writing-review-research.md)를 읽는다.

검토만 요청받았다면 파일을 고치지 않고 발견한 부분과 수정안을 보고한다. 수정 요청에는 본문을 고친 뒤 원자료와 다시 대조한다. `developer-blog-writer`가 이 스킬을 호출한 경우에는 초안 전달 전에 검토를 끝내고, 전달할 때 중요한 수정과 저자 확인 사항만 요약한다.

근거 있는 주장, 숫자, 코드, 명령, 설정, 프런트매터, 링크와 의도적인 문체를 보존한다. 직접 겪은 일이나 기술 결과를 만들어 넣지 않는다. 종결어미를 의무화하거나 금지하지 않는다. 저장소의 기존 글은 문체·구성 견본으로 삼지 않으며 필요할 때 사실 관계를 잇는 데만 참고한다. 사용자가 제공한 자료와 표현 선호를 우선한다.
