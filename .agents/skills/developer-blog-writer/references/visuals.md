# 설명용 애니메이션과 인터랙션

글의 핵심 메커니즘이나 비교가 정적인 문장·표만으로 잘 드러나지 않을 때 사용합니다. 시각 요소 자체를 목표로 삼지 말고, 독자가 장면을 보고 답할 질문을 먼저 정합니다. 아이디어와 원본 사례는 저장소의 [`docs/interactive-article-ideas.md`](../../../../docs/interactive-article-ideas.md)에 있습니다. 새 장면을 기획하거나 레퍼런스를 요청받았을 때 읽습니다.

## 장면 선택

- 시간이 지나며 상태가 바뀌는 과정은 짧은 자동 애니메이션으로 보여줍니다. 이 블로그의 기본 선호는 화면에 보일 때 반복 재생하는 방식입니다. 시작과 끝, 실패와 복구, 두 경로의 차이가 루프 경계에서도 명확해야 합니다.
- 독자가 조건을 바꿔 결과를 비교해야 한다면 버튼·프리셋·슬라이더를 사용합니다. 조작 직후 무엇이 바뀌었는지 결과 문장과 장면에 함께 표시합니다.
- 단계마다 판단해야 하는 복잡한 과정에는 이전·다음·재생·다시 보기 같은 컨트롤을 고려합니다. 짧고 자명한 루프에 불필요한 컨트롤을 붙이지 않습니다.
- 정량 그래프는 축·단위·데이터 출처를 적습니다. 교육용 모형의 단계 수나 가상 수치를 실제 성능·측정 결과처럼 표현하지 않습니다.
- 장면의 데이터와 상태 전환은 해당 글에 둡니다. 여러 글에서 반복되는 화면 틀과 재생 조건만 공통 컴포넌트로 추출합니다.

## 저장소에서 구현할 때

- 시각 요소가 필요할 때만 MDX를 사용합니다. 공통 화면 틀과 현재 사용처는 [`src/components/blog/README.md`](../../../../src/components/blog/README.md)를 확인합니다.
- 단순 반복은 CSS, 여러 상태가 이어지는 장면은 Motion, 입력에 따라 계산 결과가 바뀌는 모형은 필요한 범위의 JS/SVG/Canvas를 선택합니다. 도구보다 설명해야 할 상태와 조작을 먼저 정합니다.
- 자동 재생은 화면 밖과 비활성 탭에서 멈추게 합니다. `prefers-reduced-motion`에서는 핵심 결과가 읽히는 정지 화면을 제공합니다. 라이트·다크 모드와 키보드 조작을 확인하고, 색만으로 성공·실패를 구분하지 않습니다.
- 글의 관련 문단 가까이에 장면을 배치하고 짧은 캡션에 독자가 볼 차이와 모형의 한계를 적습니다. 장면 없이도 글의 주장이 이해되도록 본문에 핵심 내용을 남깁니다.
- 변경 후 빌드와 실제 브라우저에서 초기 상태, 자동 재생, 사용자 조작, 반응형 화면을 필요한 만큼 확인합니다.

참고 사이트는 설명 방식의 영감입니다. 코드·이미지·고유한 문장을 복사하지 않으며, 기술 주장에 필요한 근거는 별도로 확인합니다.
