# 설명용 애니메이션과 인터랙션

글의 핵심 메커니즘이나 비교가 정적인 문장·표만으로 잘 드러나지 않을 때 사용합니다. 시각 요소 자체를 목표로 삼지 말고, 독자가 장면을 보고 답할 질문을 먼저 정합니다.

이 문서는 **글을 쓰는 단계에서 장면을 기획**하는 기준입니다. 장면을 실제로 만들거나 고칠 때는 `blog-interactive-demo` 스킬을 따르고, 품질 기준인 [`docs/animation-standards.md`](../../../../docs/animation-standards.md)를 먼저 읽습니다. 품질의 기준 사례는 `src/content/blog/peekcart-monolith-peel-order.mdx`의 세 장면입니다. 아이디어와 외부 사례는 [`docs/interactive-article-ideas.md`](../../../../docs/interactive-article-ideas.md)에 있습니다.

## 기획: 장면이 보여줄 한 가지 변화

- 장면마다 독자가 *볼* 변화를 한 문장으로 씁니다. 예: "import 화살표만 믿고 Product를 떼면, 숨어 있던 호출이 끊어지며 부팅이 실패한다." 이 문장을 쓸 수 없으면 장면이 필요 없거나, 장면을 둘로 나눠야 합니다.
- 패널이나 텍스트 목록을 바꿔 끼우는 장면은 기준에 못 미칩니다. 글이 말하는 움직임(뒤집힌다, 끊긴다, 옮겨진다, 비어 간다)이 화면에서 실제로 일어나야 합니다.
- 형태는 다음 순서로 고려합니다.
  1. **직접 해 보기**: 독자가 예측하고 틀려 볼 수 있을 때 가장 강합니다.
  2. **시선 바꾸기**: 같은 대상을 두 기준으로 볼 때 씁니다.
  3. **타임라인**: 순서 자체가 내용일 때 씁니다. 화면에 보일 때 자동으로 진행하고, 독자가 단계를 누르면 멈춥니다.
- 반복 재생은 데이터가 흐르는 방향처럼 의미가 있을 때만 씁니다.
- 독자가 무언가를 발견하게 만드는 장면은 그 내용을 본문이 밝히기 *전*에 둡니다. 결과를 읽고 확인하는 장면은 관련 문단 바로 뒤에 둡니다.

## 글과 장면의 관계

- 장면 없이도 글의 주장이 이해되도록 본문에 핵심 내용을 남깁니다.
- 장면은 글에 없는 사실을 만들어 내지 않습니다. 단순화한 부분, 그리지 않은 경로, 예시로 만든 메시지는 장면 아래 안내문(`db-demo-disclaimer`)에 적습니다.
- 정량 그래프는 축·단위·데이터 출처를 적습니다. 교육용 모형의 단계 수나 가상 수치를 실제 성능·측정 결과처럼 표현하지 않습니다.
- 같은 글 안에서는 같은 대상(서비스, 테이블 등)에 같은 색을 씁니다.

## 저장소에서 구현할 때

- 시각 요소가 필요할 때만 MDX를 사용합니다.
- 구현은 장면 키트(`src/scripts/blog/scene/`, `src/styles/scene.css`)로 합니다. 의미에 맞는 움직임은 `docs/animation-standards.md`의 "모션 어휘" 표에서 고릅니다.
- 부품은 개발 서버의 `/dev/scene-kit/`에서 직접 재생해 볼 수 있습니다.
- 글별 데이터와 장면 구성은 해당 글의 컴포넌트에 두고, 여러 글에서 반복되는 부품은 키트로 올립니다.
- 완성 전에 개발 서버의 `/preview/<slug>/`(draft도 보임)에서 기준 문서의 완성 체크리스트를 확인합니다: 모든 조작, 본문 폭과 좁은 화면, 라이트·다크 모드, 움직임 줄이기 설정.

참고 사이트는 설명 방식의 영감입니다. 코드·이미지·고유한 문장을 복사하지 않으며, 기술 주장에 필요한 근거는 별도로 확인합니다.
