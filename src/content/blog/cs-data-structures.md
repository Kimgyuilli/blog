자료구조는 데이터를 담는 그릇이 아니라, **데이터에 어떤 비용으로 접근할지 결정하는 설계**다. 같은 데이터도 배열에 넣느냐, 해시 테이블이나 트리에 넣느냐에 따라 조회·삽입·삭제 비용과 메모리 사용 방식이 달라진다.

## 복잡도부터 읽기

- `O(1)`은 입력 크기와 무관하게 일정한 수의 연산이 필요하다는 뜻이다.
- `O(log n)`은 단계마다 탐색 범위가 일정 비율로 줄어든다.
- `O(n)`은 입력 크기에 비례해 원소를 확인한다.
- 분할 상환 복잡도는 여러 연산의 총비용을 장기적으로 나눈 값이다. 동적 배열의 끝 삽입이 대표적이다.

공간 복잡도도 함께 봐야 한다. 배열, 연결 리스트, 해시 테이블, 트리는 모두 값 `n`개를 저장하므로 점근적으로 `O(n)`이지만 실제 비용은 다르다. 연결 리스트는 노드와 포인터, 해시 테이블은 여유 버킷, 트리는 자식 참조를 추가로 가진다.

## 배열: 빠른 임의 접근

배열은 원소를 연속된 공간에 둔다. 시작 주소와 원소 크기를 알면 `시작 주소 + 인덱스 × 원소 크기`로 위치를 계산할 수 있어 인덱스 조회가 `O(1)`이다. 연속 배치 덕분에 순회 시 CPU 캐시도 효율적으로 활용한다.

동적 배열은 공간이 모자라면 더 큰 배열을 만들고 기존 원소를 복사한다. 확장이 일어난 한 번은 `O(n)`이지만 매번 발생하지 않으므로 끝 삽입은 분할 상환 `O(1)`이다. 반면 중간 삽입과 삭제는 뒤 원소를 이동해야 해 `O(n)`이다.

## 연결 리스트: 위치를 알 때 빠른 연결 변경

연결 리스트는 각 노드가 다음 노드를 가리킨다. 이중 연결 리스트는 이전 노드도 함께 가리킨다. 연속 메모리가 필요 없고, 삭제할 노드와 인접 노드를 이미 알고 있다면 포인터 몇 개만 바꿔 `O(1)`에 삽입·삭제할 수 있다.

하지만 특정 인덱스나 값을 찾으려면 처음부터 연결을 따라가야 하므로 `O(n)`이다. 노드가 메모리에 흩어질 수 있어 배열보다 캐시 지역성도 불리하다. 따라서 “연결 리스트의 삽입·삭제는 항상 빠르다”는 설명에는 **위치를 이미 안다**는 조건이 붙는다.

## 해시 테이블: 키로 바로 찾기

해시 테이블은 키를 해시 함수에 넣어 버킷 위치를 계산한다. 충돌이 적고 적재율이 적절하면 조회·삽입·삭제가 평균 `O(1)`이다. Map과 Set, 중복 확인, 빈도 계산, 캐시 인덱스에 잘 맞는다.

서로 다른 키가 같은 버킷을 가리키는 충돌은 체이닝이나 개방 주소법으로 처리한다. 충돌이 몰리면 최악에는 `O(n)`까지 느려질 수 있고, 버킷이 차면 더 큰 배열로 재해싱해야 한다. 객체를 키로 쓸 때는 동등성 규칙과 해시 규칙이 일치해야 하며 키는 불변으로 다루는 편이 안전하다.

## 트리, BST, 힙

트리는 부모와 자식의 계층 관계를 표현한다. 이진 탐색 트리(BST)는 왼쪽에 작은 값, 오른쪽에 큰 값을 두어 탐색한다. 연산 비용은 높이 `h`에 비례하므로 균형 트리는 `O(log n)`, 한쪽으로 편향된 트리는 최악 `O(n)`이다. AVL과 Red-Black Tree는 높이를 제한하기 위해 균형을 유지한다.

힙은 BST와 목적이 다르다. 최소 힙은 부모가 자식보다 작고, 최대 힙은 부모가 자식보다 크다는 **부분적인 우선순위**만 보장한다. 루트 확인은 `O(1)`, 삽입과 루트 삭제는 `O(log n)`이어서 우선순위 큐에 적합하다. 임의 값 탐색은 `O(n)`이다.

## 선택 기준

| 요구사항 | 적합한 구조 |
| --- | --- |
| 인덱스로 자주 접근하고 순회한다 | 동적 배열 |
| 위치를 아는 노드를 자주 연결·해제한다 | 연결 리스트 |
| 정확한 키 일치를 빠르게 찾는다 | 해시 테이블 |
| 정렬 순회와 범위 검색이 필요하다 | 균형 BST |
| 가장 작거나 큰 원소를 반복해서 꺼낸다 | 힙 |

자료구조 선택은 Big-O 하나로 끝나지 않는다. 실제 연산의 비율, 메모리 오버헤드, 캐시 지역성, 정렬 필요 여부까지 함께 보는 것이 핵심이다.
