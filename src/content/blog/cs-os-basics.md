프로그램은 저장 장치에 있는 정적인 명령과 데이터다. 실행되면 운영체제로부터 주소 공간과 자원을 할당받은 **프로세스**가 되고, 프로세스 안에서 CPU가 실제로 실행하는 흐름이 **스레드**다. 이 세 개념을 구분하면 스케줄링과 컨텍스트 스위칭도 자연스럽게 이어진다.

## 프로세스는 자원과 격리의 단위

프로세스는 코드, 전역·정적 데이터, 힙, 스택, 메모리 매핑 영역으로 구성된 가상 주소 공간을 가진다. 열린 파일과 소켓, 권한, PID, 상태와 우선순위 같은 정보도 포함한다. 운영체제는 이를 PCB 또는 그에 준하는 커널 자료구조로 관리한다.

프로세스의 대표적인 상태는 다음과 같다.

- **Ready**: 실행 조건은 갖췄지만 CPU를 기다린다.
- **Running**: 현재 CPU에서 실행 중이다.
- **Waiting/Blocked**: I/O, 락, 타이머 등의 조건을 기다린다.
- **Terminated**: 실행을 마치고 종료 처리 중이다.

Ready와 Waiting의 차이가 중요하다. Ready는 CPU만 받으면 진행할 수 있지만 Waiting은 CPU를 줘도 대기 조건이 충족되기 전에는 진행하지 못한다.

프로세스는 주소 공간과 권한이 분리되어 장애·보안 격리가 강하다. 반면 생성과 종료 비용이 상대적으로 크고 데이터를 나누려면 파이프, 소켓, 공유 메모리 같은 IPC가 필요하다.

## 스레드는 실행의 단위

같은 프로세스의 스레드는 코드, 전역 데이터, 힙, 열린 파일을 공유한다. 각 스레드는 프로그램 카운터, CPU 레지스터, 사용자·커널 스택, 스레드 ID와 스케줄링 상태를 따로 가진다.

스레드는 한 흐름이 I/O를 기다릴 때 다른 흐름을 실행해 응답성을 높이고, 같은 주소 공간에서 데이터를 빠르게 공유하며, 여러 코어를 활용할 수 있게 한다. 하지만 공유 메모리는 race condition, deadlock, livelock, starvation의 가능성도 만든다. 락 경쟁과 캐시 일관성 비용 때문에 스레드를 늘린다고 처리량이 항상 증가하지는 않는다.

“스레드는 프로세스보다 가볍다”는 말은 같은 프로세스의 자원을 재사용해 생성·통신·주소 공간 전환 부담이 보통 작다는 뜻이다. 스택, 커널 관리 정보, 스케줄링과 동기화 비용은 여전히 존재한다.

## 동시성과 병렬성

동시성은 여러 작업의 진행 구간이 겹치는 성질이다. 단일 코어에서도 빠르게 번갈아 실행하면 가능하다. 병렬성은 같은 순간에 여러 작업이 실제로 실행되는 성질이며 보통 여러 코어가 필요하다.

따라서 스레드가 여러 개라는 사실만으로 병렬 실행이 보장되지는 않는다. 코어 수, runnable 스레드 수, 스케줄러, 락, I/O 대기 상태가 함께 결정한다.

## 컨텍스트 스위칭

컨텍스트 스위칭은 CPU가 현재 스레드나 태스크의 실행 문맥을 저장하고 다음 대상의 문맥을 복원하는 과정이다. 프로그램 카운터, 스택 포인터, 범용·상태 레지스터와 커널 스택 등의 상태가 대상이 된다. 서로 다른 프로세스로 전환하면 주소 공간 관련 문맥도 바뀔 수 있다.

블로킹 I/O, 락·이벤트 대기, `sleep`, `yield`처럼 실행 주체가 스스로 CPU를 내놓는 경우는 자발적 전환이다. 타임 슬라이스 소진이나 더 높은 우선순위 작업의 등장으로 선점되는 경우는 비자발적 전환이다.

전환에는 문맥 저장·복원과 다음 작업 선택이라는 직접 비용이 든다. 새 작업의 코드와 데이터가 캐시에 없어 생기는 cache miss, 주소 변환 캐시(TLB) 부담, 코어 이동에 따른 지역성 손실 같은 간접 비용도 있다. 프로세스가 바뀐다고 현대 CPU의 TLB가 반드시 전부 비워지는 것은 아니지만, 다른 주소 공간으로의 전환은 같은 프로세스 안의 스레드 전환보다 일반적으로 더 많은 부담을 줄 수 있다.

## 자주 헷갈리는 경계

- **시스템 콜은 항상 컨텍스트 스위칭인가?** user mode에서 kernel mode로 바뀌어도 같은 스레드가 계속 실행되면 모드 전환일 뿐이다. I/O 대기로 다른 스레드가 선택될 때 컨텍스트 스위칭도 발생한다.
- **인터럽트는 항상 컨텍스트 스위칭인가?** 처리 후 원래 스레드로 복귀할 수도 있다. 스케줄러가 실행 대상을 바꿀 때만 컨텍스트 스위칭이다.
- **CPU-bound 작업은 스레드가 많을수록 좋은가?** runnable 스레드가 코어 수보다 지나치게 많으면 전환과 경쟁 비용만 커질 수 있다.

입문 단계의 가장 유용한 정신 모델은 **프로세스는 자원 소유·보호·격리 단위, 스레드는 실행·스케줄링 단위**라는 구분이다. 실제 OS 구현은 더 복잡하지만 성능과 동시성 문제를 추론할 출발점이 된다.
