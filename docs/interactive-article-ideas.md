# 기술 글의 애니메이션·인터랙션 아이디어

2026-10-01 조사. 아래 링크는 **설명 방식의 참고 사례**입니다. 해당 사이트의 코드·그림·문장을 복사하는 목록이 아닙니다. 기술적 사실은 글의 실제 코드, 측정 결과, 공식 문서로 별도 검증합니다.

## 글에 적용할 패턴

| 패턴 | 독자가 확인할 질문 | 적용할 만한 글 | 구현 방향 |
| --- | --- | --- | --- |
| 동기화된 두 경로 | 같은 입력이 조건에 따라 어떻게 갈라지는가? | 캐시 히트/미스, 동기/비동기 처리, 정상/롤백, 순차 스캔/인덱스 | 두 장면의 시간을 맞추고 각 경로의 결과를 끝에 함께 남긴다. `AutoMotionFigure` 또는 Motion 장면을 활용한다. |
| 상태 타임라인 | 어느 단계에서 값이 바뀌거나 실패했는가? | Outbox, 재시도·DLQ, 트랜잭션, Kubernetes 조정 루프 | 자동 재생에 이전·다음·처음부터 보기와 현재 단계 설명을 붙인다. 같은 조작이 두 글 이상에 쓰일 때 단계 컨트롤을 공통화한다. |
| 조건 조절 실험 | 입력을 바꾸면 결과가 어떻게 달라지는가? | 동시 요청 수와 풀 크기, 캐시 TTL, 큐 처리량, 인덱스 선택도 | 슬라이더·프리셋으로 작은 결정적 모형의 입력을 바꾼다. 실제 성능 수치처럼 보이지 않게 단위와 모형의 한계를 표시한다. |
| 문장과 그림의 연결 | 설명 중인 값이 그림의 어느 부분인가? | SQL의 `JOIN ON`, 외래 키, 쿼리 실행 계획, 요청 흐름 | 문장 속 키워드에 포커스하거나 마우스를 올리면 표의 행·열·경로를 함께 강조한다. 키보드 포커스에도 같은 반응을 준다. |
| 실패 지점 선택 | 실패 위치가 달라지면 최종 상태는 어떻게 되는가? | 결제·주문 트랜잭션, 메시지 중복 처리, 네트워크 재시도 | 2~3개의 실패 프리셋을 고르게 하고 성공한 단계·취소된 단계·남은 상태를 같은 화면에서 갱신한다. |
| 기준선 겹쳐보기 | 값 하나 대신 두 지표나 두 시점을 함께 보면 무엇이 드러나는가? | P50/P99, 배포 전후, 캐시 히트율과 DB 부하, CPU와 대기 시간 | 두 곡선을 같은 축에 놓고 한쪽을 켜고 끈다. 축·단위·데이터의 출처를 명시한다. |

## 공통 컴포넌트로 만들 기준

현재 공통 부품은 [`src/components/blog/README.md`](../src/components/blog/README.md)에 정리되어 있습니다. 위 표의 장면 자체는 글의 데이터와 결론에 따라 달라집니다. **서로 다른 글에서 같은 조작과 접근성 동작이 반복될 때** 단계 재생기, 비교 전환기, 연결 강조 기능을 별도 공통 컴포넌트로 추출합니다.

새 장면은 정지 상태에서도 핵심 결과를 읽을 수 있어야 합니다. 자동 재생은 화면 밖이나 비활성 탭에서 멈추고, 움직임 줄이기 설정에는 완결된 정지 화면을 제공합니다. 색상은 라이트·다크 모드에서 확인하고, 색만으로 결과를 구분하지 않습니다.
